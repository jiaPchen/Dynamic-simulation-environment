# 阶段一仿真测试系统全景梳理

> 目的：说明 `00trucksim_simulink` 中阶段一资产如何从工况 TXT、第一轴转向输入、TruckSim/Simulink 仿真一直走到 CSV 与 Word 报告。本文描述当前源代码与保留产物，不把历史报告视为本机环境已验证的结论。

## 1. 一句话总览

阶段一是一个开环的单车动力学测试系统：MATLAB 根据 TXT 生成第一轴转角，Simulink 将其送入 TruckSim S-Function，TruckSim 输出车辆状态，MATLAB 导出 CSV，Python 生成曲线和 Word 报告。

```text
TXT case
   │
   ▼
run_case_new.m
   │ ├─ parse_case.m
   │ ├─ steer_input timeseries
   │ ├─ trucksim_config.m → COM / .par 回退配置
   │ ├─ TruckSim S-Function 的 SIMFILE
   │ └─ sim(..., StopTime) → validate_simulation_output.m
   ▼
Simulink / TruckSim
   │ └─ To Workspace: t, Vx, beta, w, x, y, xt, yt, delta
   ▼
export_case_csv.m
   ▼
make_test_report_new.py
   ▼
CSV + PNG + DOCX + report_manifest.json
```

它不包括 Python 控制器、TCP 状态交换或二/三轴转向分配。那些能力属于同级 `01_trucksim_simulink_python` 的阶段二项目。

## 2. 架构层次与文件关系

| 层 | 文件/目录 | 输入 | 输出 | 职责 |
| --- | --- | --- | --- | --- |
| 工况层 | `02_测试用例/*.txt` | 人工编辑的参数 | 结构化键值 | 定义名称、时长、转向类型、幅值、频率和标称速度。 |
| 编排层 | `run_case_new.m` | 用例与本机路径 | 仿真调用、运行编号 | 单次运行的唯一入口；先配置后仿真。 |
| 模型层 | `new_three_axle_vehicle_2dof_3dof_Trucksim.slx` | 第一轴转向、`simfile.sim` | TruckSim 输出 | 保留 TruckSim 的输入/输出接口。 |
| 参数层 | `three_parameter1.m` | 车辆基础参数 | 模型可用参数 | 保留三轴车辆模型的参数依据。 |
| 导出层 | `export_case_csv.m` | To Workspace 信号和用例 | IO CSV、case info CSV | 保存原始仿真信号和当次用例元数据。 |
| 报告层 | `make_test_report_new.py` | CSV、用例信息 | PNG、DOCX、JSON | 计算描述性指标并输出报告。 |
| 修复/配置层 | `repair_model_new.m`、`trucksim_config.m`、`configure_trucksim_case.py`、`validate_simulation_output.m` | 模型/用例/输出 | 模型修复、TruckSim 工况配置或导出前验收 | 前者仅用于模型接线恢复；后两项配置 TruckSim 并验证时长、首车速和转向。 |

## 3. 工况与控制流

### 3.1 用例解析

`parse_case.m` 要求 TXT 至少包含 `case_name`、`stop_time_s`、`initial_speed_kmh` 和 `steer_input_type`，并检查数值范围。当前 4 个基准用例覆盖 20/40 km/h 正弦转向和 30/40 km/h 阶跃转向。

### 3.2 第一轴转向生成

`run_case_new.m` 以 0.001 s 创建时间向量：

- 正弦输入：在 `steer_start_time_s` 之后生成 `A sin(2πf(t-t0))`；
- 阶跃输入：在 `steer_start_time_s` 之后维持 `A` 度；
- 该 `timeseries` 被命名为 `steer_input` 并放入 MATLAB base workspace。

模型的 `Steering Input` 块从 workspace 读取 `steer_input`。根据入口脚本注释，它只驱动 Mux 的第一轴左右两个通道；第二、三轴转角固定为 0 度。因此阶段一的结果解释为“前轴输入下的三轴车辆响应”，不能解释为多轴主动转向效果。

### 3.3 TruckSim 工况边界

脚本会把 `trucksimSimFile` 写入 `TruckSim S-Function2` 的 `SIMFILE` 参数，并把 solver 的 `Matlab84+` 目录加入 MATLAB 路径。默认启用 TruckSim 工况配置：COM 不可用时修改当前 `simfile.sim` 指向的 `.par` 参数文件，并在导出前验证时长、初始速度和实际转向。

历史结果可能存在两套概念；当前严格入口会阻止这种不一致继续归档：

| 内容 | 事实来源 |
| --- | --- |
| 转向形状、幅值、频率、开始时间、停止时间 | 当前 TXT 与 MATLAB 脚本。 |
| TruckSim 实际初始车速、道路和车辆工况 | 当前 `simfile.sim` 与 TruckSim Run。 |
| 报告中的“用例速度” | TXT 记录值。 |
| 报告中的“实际起始车速” | TruckSim 导出首个车速值。 |

当前严格入口会在两类速度的初始值不同时停止归档。它不校验整个过程中的稳态速度跟踪，因此“初始车速正确但稳态偏离目标”应单独作为车辆/速度控制响应问题记录，而不是把 CSV 改成目标速度。

## 4. 数据与报告链路

仿真结束后，入口脚本从 `SimulationOutput` 中导出以下信号：

| CSV 列 | To Workspace 变量 | 含义 | 单位 |
| --- | --- | --- | --- |
| `sim_time_s` | `t` | 仿真时间 | s |
| `state_vehicle_speed_kmh` | `Vx_trucksim` | 车辆纵向速度 | km/h |
| `state_beta_trucksim_deg` | `beta_trucksim` | 质心侧偏角 | deg |
| `state_yaw_rate_trucksim_degps` | `w_trucksim` | 横摆角速度 | deg/s |
| `state_x_m` / `state_y_m` | `x_trucksim` / `y_trucksim` | 车辆位置 | m |
| `state_xt_m` / `state_yt_m` | `xt_trucksim` / `yt_trucksim` | 挂车位置 | m |
| `state_steer_delta_deg` | `delta_input` | 第一轴转向输入 | deg |

报告脚本基于这些 CSV 计算累计行驶距离、最大横向位移、最大横摆角速度和最大质心侧偏角等描述性指标，并输出速度、侧偏角、横摆、轨迹、位置、转向等图。`report_manifest.json` 记录本次报告引用的输入与生成文件，便于追溯。

## 5. 结果目录与历史证据

单次运行的典型结构：

```text
03_数据存储/<用户目录>/<运行编号>/
  <运行编号>_trucksim_io.csv
  <运行编号>_case_info.csv

04_测试报告/<运行编号>/
  阶段一车辆动力学仿真测试报告.docx
  report_manifest.json
  *.png
  <用例副本>.txt
```

运行编号由 `export_case_csv.m` 在 `03_数据存储` 的全部类别中取最大“第NNN次”再加 1；因此新运行跨正弦/阶跃统一递增。早期目录保留了按类别计数时产生的重复编号，不能仅凭编号判断先后，应同时查看目录时间。

近期第013至第017次验证了新流程：实际结束时间、初始车速和第一轴转向均通过导出前验证，且每个完整报告都有 8 张曲线图。第017次是临时命名为 `step_steer_25kmh` 的 25 km/h 阶跃试验，其报告缺少 TXT 副本，故仅可作为响应参考，不可当作完整可复现实验档案。20 km/h 正弦在第015、016次的稳态速度约为 21.11 km/h，属于后续可调校的速度保持响应观察项。

## 6. 当前状态与风险边界

### 当前可用资产

- 模型、车辆参数脚本、用例解析、CSV 导出、报告脚本和历史产物均在目录中。
- 当前 4 个基准 TXT 的 `case_name` 与文件名相匹配，便于追溯。
- `repair_model_new.m` 提供了标准接线恢复工具，但它不是日常运行前置步骤。

### 首次本机运行前的风险

1. **软件绝对路径依赖本机。** 项目内文件路径已相对定位；但 Python、TruckSim solver 和 `simfile.sim` 仍需在换机后核对并改为实际位置。
2. **TruckSim 参数文件是共享外部状态。** 每次运行会修改当前 `simfile.sim` 指向的 `.par` 文件；应确认当前 TruckSim Run 正确，且不要并行运行阶段一、阶段二。
3. **模型接线不能只靠文件名推断。** 若缺少 `Steering Input` 或 `TruckSim S-Function2`，应先备份并检查，再由维护者决定是否运行修复脚本。
4. **验收范围有限。** 当前已自动拦截配置、结束时间、初始车速和第一轴转向不一致；但报告生成仍不等于动力学模型通过技术指标，尚没有统一阈值、失败分类、稳态速度跟踪判据或批量回归策略。

## 7. 与阶段二的关系

阶段一提供车辆模型、基准工况和单轴开环响应的基础；阶段二在独立文件夹中将 Python 控制器和 TCP 通讯引入模型，输出六路轮端转角。阶段一当前复用了阶段二的 TruckSim COM/`.par` 配置模块，因此二者既共享部分代码，也共享实际 `simfile.sim` 所关联的 TruckSim 参数状态。

阶段一和阶段二的报告不可直接横向比较，除非统一以下条件：TruckSim Run/车辆参数、simfile、道路、初始速度、转向输入定义、时间轴和输出信号单位。特别是阶段一第二、第三轴恒为 0 度，而阶段二会主动分配二、三轴转角。

## 8. 推荐维护顺序

1. 适配路径后先运行一个单工况，确认模型、solver、simfile、CSV 和报告链路。
2. 比较 CSV 首行车速与 TXT 标称速度；若不一致，先在 TruckSim 中确认而不是修改结果文件。
3. 备份 `.slx` 后才考虑模型接线修复或参数修改。
4. 如要建立批量/验收能力，应保持当前“先配置、后仿真、再验收”的顺序，并增加单独的批量入口、稳态速度跟踪判据和明确的动力学指标阈值。
