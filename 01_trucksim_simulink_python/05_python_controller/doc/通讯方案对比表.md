# Python ↔ Simulink 通讯方案对比（阶段二）

> 结论：第一阶段采用**本机 TCP Socket + JSON 行协议**（127.0.0.1 固定端口，0.01 s 周期），
> 与《02_详细方案_TruckSim_Simulink_Python联仿》的约定一致，实现简单、调试友好、无额外工具箱依赖。

| 方案 | 实时性/确定性 | 实现复杂度 | 依赖/工具 | 调试与可维护性 | 后续扩展（HIL/分布式） | 结论 |
|---|---|---|---|---|---|---|
| TCP Socket（本机） | 好：0.01 s 周期内稳定，偶发 OS 调度抖动 | 低：Simulink 端 Level-2 M S-Function + Python socket | 仅 MATLAB 内建 Java、Python 标准库 | 好：JSON 文本可读，可用网络调试工具抓包 | 中：换 IP/端口即可跨机 | ✅ 采用 |
| UDP（本机） | 好：延迟更低 | 低 | 同 TCP | 差：丢包需自行处理，无应答确认 | 中 | 备选（后续需要更低延迟时） |
| 共享内存/内存映射文件 | 最好：微秒级 | 高：Simulink 端需 C MEX 或 Java MMF，Python 端需 mmap 协议 | pywin32 / MEX | 差：二进制结构，协议变更成本高 | 仅限同机 | 暂不采用 |
| 文件交换（To/From Workspace） | 差：无法步内闭环 | 低 | 无 | 好 | 无 | 仅适合离线前馈 |
| MATLAB Python 引擎（py.*） | 差：仿真阻塞、版本耦合 | 中 | MATLAB版本兼容性 | 中 | 无 | 不采用 |
| COM/ActiveX | 中 | 高：接口晦涩 | MATLAB COM、pywin32 | 差 | 中 | 不采用 |
| gRPC / WebSocket | 中：HTTP/2 开销 | 高：需第三方库与代码生成 | 第三方 Python 包 | 中 | 好 | 后续算法服务化时再评估 |
| 命名管道（Named Pipes） | 好 | 中：Simulink 端需 MEX | pywin32 | 差 | 仅限同机 | 备选 |

## 已实现方案说明

- **位置**：`127.0.0.1:50007`（可在 `tcp_client_sfun.m` 与 `tcp_server.py` 中统一修改）。
- **报文**：UTF-8 单行 JSON，`HELLO/READY/STATE/CONTROL/RESET/STOP`，STATE 与 CONTROL 携带相同 `step_id`。
- **周期**：0.01 s（Simulink 侧 S-Function 采样周期 = Python 侧 `control_dt_s`）。
- **Simulink 侧**：`tcp_client_sfun.m`（Level-2 M S-Function，用 Java Socket），输入 3 状态、输出 6 转角。
- **Python 侧**：`tcp_server.py`（零质心侧偏角控制器 + 数据记录）。

## 后续优化方向

1. 若 0.01 s 周期出现抖动，可将 JSON 报文换成定长二进制（字段不变，仅序列化层替换）。
2. 需要跨机器运行时，改服务器绑定地址与防火墙规则即可。
3. 批量工况建议每个工况独立启动/停止服务进程，避免状态串扰（当前脚本已按此实现）。
