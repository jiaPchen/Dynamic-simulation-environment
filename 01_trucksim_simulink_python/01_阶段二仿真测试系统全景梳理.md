# 阶段二仿真测试系统全景梳理

> 目的：说明当前 `动力学仿真环境阶段二` 文件夹中的真实资产、控制链路、数据链路、结果边界和维护重点。
## 1. 一句话总览

阶段二是一个由 MATLAB 脚本编排的单机联合仿真系统：TXT 用例定义工况，Python 服务按零质心侧偏角控制律计算三轴六轮转角，Simulink 在 TCP 中转状态和控制量，TruckSim 计算车辆响应，最后由 MATLAB/Python 导出 CSV、绘制曲线并生成 Word 报告。

```text
TXT case
   │
   ▼
run_case_python.m / run_batch_python.m
   │
   ├─ run_single_python_case.m ── 解析用例、设置模型、启动 Python
   │                                      │
   │                                      ▼
   │                            tcp_server.py
   │                            ├─ 配置 TruckSim
   │                            └─ zero_sideslip_controller.py
   ▼                                      ▲
Simulink 模型 ── TruckSim S-Function ── TCP Client S-Function
   │                                      │
   └──────── out / CSV ───────────────────┘
                     │
                     ▼
make_report_python.py / make_batch_summary.py
                     │
                     ▼
CSV、PNG、DOCX
```

## 2. 本目录范围

本文只解释 `01_trucksim_simulink_python/` 内的阶段二文件。该目录自身包含运行所需的 Simulink 模型、MATLAB 脚本、TXT 用例、Python 控制器、历史数据和报告；日常运行根目录即为本目录。

同一时刻只允许一个实例修改同一套 TruckSim Run、`simfile.sim` 和关联 `.par` 参数文件，避免外部工况状态互相覆盖。

## 3. 组件分层与职责

| 层 | 组件 | 输入 | 输出 | 主要责任 |
| --- | --- | --- | --- | --- |
| 用例层 | `02_测试用例/*.txt` | 人工定义的工况参数 | 键值配置 | 定义速度、时长、转向激励、控制增益、附着系数。 |
| 编排层 | `run_case_python.m`、`run_batch_python.m`、`run_single_python_case.m` | 用例、电脑路径 | 启动顺序、运行目录 | 串起 MATLAB、TruckSim、Python 与报告生成。 |
| 联仿中间层 | `tcp_client_sfun.m` | TruckSim 状态 | 6 路轮端转角 | 按 JSON 行协议作为 Simulink TCP 客户端。 |
| 动力学层 | TruckSim S-Function 与外部 TruckSim 数据目录 | 6 路转角、工况参数 | 车速、质心侧偏角、横摆角速度、位置等 | 求解三轴车辆动力学。 |
| 控制层 | `zero_sideslip_controller.py` | 车速、beta、横摆角速度、用例 | 各轴/轮端转角与诊断量 | 执行前馈+PI 的多轴分配控制。 |
| 工况配置层 | `trucksim_com.py`、`vehicle_config.yaml` | TXT 与 YAML | COM 写入或 `.par` 修补 | 确保 TruckSim 尽量按 TXT 实际运行。 |
| 记录与报告层 | CSV 导出、`make_report_python.py`、`make_batch_summary.py` | MATLAB 与 Python 信号 | CSV、PNG、Word | 形成可读结果和原始追溯材料。 |

## 4. 控制与数据如何流动

### 4.1 工况参数流

```text
*.txt
  ├─ MATLAB parse_case.m：本地校验
  ├─ Python parse_case_py.py：服务端校验
  ├─ run_single_python_case.m：设置 StopTime
  ├─ tcp_server.py：设置控制周期并加载控制器
  └─ trucksim_com.py：配置 TSTOP、速度、附着系数
```

YAML 提供车辆几何、质量、惯量、轮胎等效侧偏刚度和默认控制器增益。TXT 内的 `kp_beta`、`ki_beta`、`max_steer_deg` 可以覆盖相应默认值。`road_grade` 处于保守禁用状态：格式允许，但没有目标机确认的 TruckSim 关键字映射。

### 4.2 运行时闭环

1. Python 服务先配置 TruckSim，再监听本机 TCP 端口 50007。
2. Simulink Client 发送 `HELLO`，声明协议版本、3 个输入名称与 6 个输出名称；Python 校验后回复 `READY`。
3. 每 0.01 s，Simulink 发送 `STATE(step_id, t, [Vx_kmh,beta_deg,w_degps])`。
4. Python 验证连续步号和有限数值，计算 `CONTROL(step_id, t, [d1L,d1R,d2L,d2R,d3L,d3R])` 并立即记录一行 `python_signals.csv`。
5. Simulink 把控制量接入 TruckSim；模型结束时发送 `STOP`，Python 写入 `STOP_OK` 和 `SERVER_STOPPED`。

这种握手与逐步编号的意义是：维度不一致、协议不一致、非有限状态或漏步都会让服务报错，而不会静默输出看似正常的控制量。

### 4.3 TruckSim 工况写入

配置层先尝试 COM，再回退到 `.par` 文件修补。回退路径由 `vehicle_config.yaml` 的 `trucksim.simfile_path` 决定，程序会从其 `simfile.sim` 中找到当前 `INPUT` 的 `Run_all.par`，并追踪 `ENTER_PARSFILE`、`PARSFILE` 与事件引用。

这条机制的前提是：Simulink S-Function 与 YAML 指向同一个 TruckSim 数据目录。二者不一致时，日志即使显示配置成功，也可能不是模型正在使用的工况。

## 5. 当前用例与输出证据

当前用例库包含 4 个基础工况：

| 文件 | 激励 | 初始/目标车速 | 停止时间 |
| --- | --- | ---: | ---: |
| `sine_steer_python-1.txt` | 2°、0.2 Hz 正弦，1 s 后开始 | 15 km/h | 30 s |
| `sine_steer_python.txt` | 2°、0.2 Hz 正弦，1 s 后开始 | 40 km/h | 12 s |
| `step_steer_python -20kmh.txt` | 3° 阶跃，1 s 后开始 | 20 km/h | 20 s |
| `step_steer_python.txt` | 3° 阶跃，1 s 后开始 | 40 km/h | 20 s |

每个实际运行至少应留存下列材料：

```text
<run>/
  *_case.txt                 # 当时使用的用例副本
  *_case_info.csv            # 结构化用例快照
  *_trucksim_io.csv          # MATLAB / TruckSim 导出状态与命令
  *_python_signals.csv       # Python 收发状态、控制器诊断与转角
  *_python_stdout.log        # COM/.par、握手与停止日志
  *_metrics.csv              # 汇总指标（若报告已生成）
```

批量目录进一步包含 `cases/`、`figures/`、`batch_run_dirs.txt`、`批量指标汇总.csv` 和唯一的 `阶段二批量仿真测试报告.docx`。其中 `batch_run_dirs.txt` 是批量报告追溯到各运行目录的入口。

## 6. 报告如何得出

`make_report_python.py` 会读取同一运行目录的 TruckSim IO、Python 信号和用例快照。它优先以 Python 的 `sim_time_s` 合并时间轴，再补充 TruckSim 状态；随后计算起止/最大车速、最大质心侧偏角、最大横摆角速度和各轴转角峰值，生成七类曲线和 Word 报告。

`make_batch_summary.py` 逐个加载批次中的运行目录，复制每个工况的曲线并输出汇总表。因此批量 Word 的数值来源仍是各 case 的 CSV，不会重新运行仿真。

这意味着：报告是“数据的可视化和汇总”，而非第二套独立测量。若源 CSV 的时间轴或信号映射错误，报告也会继承该错误或掩盖该错误。

## 7. 推荐使用顺序

1. 先阅读 `01_trucksim_simulink_python/换机配置与AI交接说明.md`，核对本机的 MATLAB、Python、TruckSim solver 和 `simfile.sim` 路径。
2. 在 MATLAB 运行 `run_local_preflight`，确认模型、S-Function、Python 依赖和 TruckSim 路径都存在。
3. 运行 Python 离线控制器与 TCP 测试。
4. 先跑低速单工况，复核日志中的 `CONFIG_READY` 和导出 CSV 的初始速度。
5. 对同一次单工况比较 Python 与 TruckSim IO 的时间末值；时间轴一致后再运行全部批量。
6. 仅在 CSV、日志、曲线和 Word 都齐全且关键时间/速度检查通过后，再把结果用于技术结论。

## 8. 推荐的后续完善方向

- 保留 `trucksim_io.csv` 的时间轴一致性断言；新运行时将末时间与 `stop_time_s` 的差控制在规定容差内。
- 将 TXT 的 `case_name` 设为唯一值，并在汇总 CSV 中同时保留源文件名和 `source_case_id`。
- 为每个测试用例定义目标指标、阈值和结果状态，至少区分 `PASS`、`FAIL`、`CONFIG_ERROR`、`DATA_INVALID`。
- 把本机绝对路径集中为一份机器配置，减少换机时多脚本、多 YAML 同步修改的风险。
