# 阶段二换机配置与AI执行说明

## 给新电脑AI的任务

本文件只对应当前文件夹`01_trucksim_simulink_python`。使用者把整个文件夹复制到新电脑后，将本文件提供给能访问该文件夹和目标机软件的AI，并明确要求其按本文配置。只发送说明文件而不提供项目文件夹或目标机访问权限，AI无法实际修改和验证环境。AI应自动定位并适配项目内配置，不要求使用者手工逐项填写路径模板。

本项目是TruckSim+Simulink+Python的TCP闭环联仿：MATLAB启动Python服务，Simulink每`0.01s`向Python发送车辆状态，Python返回六路轮端转角，TruckSim完成车辆动力学计算。项目运行入口在`01_一键启动脚本`。

截至 2026-09-25，旧电脑的常规目录有 2 个正弦、2 个阶跃 TXT，`run_case_python.m` 默认选用 `step_steer_python_40kmh.txt`；旧电脑四工况批量报告已记录运行完整性 `PASS`。这些历史结果只证明当时环境，不等于新电脑的预检或真实联仿已经通过。坡度、起伏路面和 COM 实测是扩展验证，不是《项目推进(1).docx》阶段二的必验项。

## AI的询问规则

AI先进行不写入的检查和路径定位；不要逐项询问Python、TruckSim或项目路径。如果使用者已明确要求配置项目、安装必要依赖和执行离线验证，直接完成这些工作；否则在定位完成后集中询问一次：

```text
已定位目标机环境和需要修改的项目配置。是否允许我修改项目内MATLAB脚本与vehicle_config.yaml、安装缺少的Python依赖，并执行只读预检和Python离线测试？
```

配置与离线验证**不包含真实仿真**。真实仿真会修改TruckSim当前Run关联的`.par`数据，需在使用者明确要求运行单工况或批量仿真后执行。若无法从文件确认当前选中的Run，AI应集中请求Run名称或TruckSim界面截图，不得猜测。

AI不得删除或批量改写`03_数据存储`、`04_测试报告`中的历史结果；不得覆盖`.slx`模型；不得修改历史CSV、Word报告、PNG、日志或其内部旧路径。

## 必须先确认的外部条件

项目文件夹不包含TruckSim软件和其数据集。当前已验证的组合为MATLAB R2024b、TruckSim 2019.0、Python 3.10.4；目标机必须具备：

1. Windows、MATLAB及Simulink。
2. TruckSim及其solver目录；solver目录内必须有`Matlab84+`子目录。
3. Python解释器。项目由MATLAB通过命令行启动Python，不使用MATLAB的`py.*`接口；Python 3.10.4为当前已验证版本，其他版本必须先通过全部离线测试。核心依赖为`numpy`、`matplotlib`、`python-docx`和`pyyaml`；`pywin32`仅用于尝试TruckSim COM，`.par`回退路径不依赖它。阶段二当前代码不要求`pandas`、`scipy`、`h5py`或`plotly`。
4. 已在TruckSim中导入本目录的`ORAC-BLFISMC1017 #phase2.cpar`，并选定要联仿的Run。
5. 已在TruckSim中对该Run执行“发送到Simulink”。此操作会生成或更新实际用于联仿的`simfile.sim`。
6. AI确认源`simfile.sim`对应阶段二Run后，在MATLAB的`01_一键启动脚本`目录运行`capture_phase2_simfile('<目标机源simfile.sim的完整路径>')`。脚本会在TruckSim数据目录生成`simfile_phase2.sim`，并更新项目内的`runtime/trucksim_phase2.path`和`trucksim_phase2.origin.txt`。

第4、5项需要在TruckSim界面完成；若AI无法操作目标机界面，应请使用者完成后继续。第6项由可操作MATLAB的AI执行。不得猜测Run名称或随意选择其他`simfile.sim`。若同级阶段一入口在新电脑有效，保存脚本会拒绝与其指向同一`Run_all.par`；若阶段一路径仍是旧电脑无效路径，只会警告并要求后续重新配置阶段一。

## AI自动检查与定位步骤

AI必须按以下顺序执行。

### 1. 定位项目和完整性检查

1. 将本文件所在目录视为阶段二项目根目录，不依赖旧电脑的盘符或桌面位置。
2. 确认以下文件存在：

```text
00_simulink/three_axle_vehicle_2dof_3dof_Trucksim_python.slx
00_simulink/tcp_client_sfun.m
01_一键启动脚本/run_case_python.m
01_一键启动脚本/run_batch_python.m
01_一键启动脚本/run_single_python_case.m
01_一键启动脚本/run_local_preflight.m
01_一键启动脚本/capture_phase2_simfile.m
02_测试用例/
runtime/README.md
05_python_controller/config/vehicle_config.yaml
05_python_controller/tcp/tcp_server.py
05_python_controller/report/make_report_python.py
05_python_controller/report/make_batch_summary.py
05_python_controller/tests/test_report.py
05_python_controller/requirements.txt
ORAC-BLFISMC1017 #phase2.cpar
```

3. 如已复制`runtime/trucksim_phase2.path`和`trucksim_phase2.origin.txt`，其内容仍记录旧电脑的TruckSim路径；不得据此认定目标机入口有效。若这两个文件不存在，也可由`capture_phase2_simfile`生成。只读检查项目源码和说明中遗留的旧项目根目录；历史数据、报告中的旧路径只作为历史记录，不修改。

### 2. 定位目标机Python和TruckSim

1. 查找可用的`python.exe`，读取版本，并用该解释器检查`yaml`、`numpy`、`matplotlib`和`docx`是否可导入；需要尝试TruckSim COM时再检查`win32com`。
2. 查找TruckSim的solver目录，确认其中存在`Matlab84+`。
3. 查找TruckSim数据目录中刚刚“发送到Simulink”生成的源`simfile.sim`；不得把项目内历史结果、任意同名文件或别的TruckSim项目的数据集当作目标文件。
4. 打开或读取该源文件，解析`INPUT`并确认关联的`Run_all.par`存在；根据TruckSim中的Run信息确认它属于阶段二，再在MATLAB的`01_一键启动脚本`目录运行`capture_phase2_simfile('<目标机源simfile.sim的完整路径>')`。不传参数时脚本默认读取旧电脑的`C:\Trucksim2019\TruckSim2019.0_Data\simfile.sim`，换机时不要依赖该默认值。
5. 检查新生成的`runtime/trucksim_phase2.path`指向目标机TruckSim数据目录中的`simfile_phase2.sim`，并确认专用入口的`INPUT`仍指向已选定的阶段二Run。若无法把参数文件对应到TruckSim界面中的Run，应请使用者提供Run名称或截图；保持YAML的`run_name`原值并报告未确认，不要猜测修改。

### 3. 检查路径一致性

阶段二有两条必须指向同一个文件的路径：

```text
MATLAB的trucksimSimFile
YAML的trucksim.simfile_path
```

两者均通过项目内`runtime/trucksim_phase2.path`定位TruckSim数据目录中的`simfile_phase2.sim`：MATLAB读取路径记录，YAML中的`${PROJECT_RUNTIME_SIMFILE}`由Python服务解析为同一路径。AI不得把它们改回共享源文件`simfile.sim`，也不得把旧电脑`.path`的内容直接沿用到新电脑。`simfile.sim`不是TruckSim界面中的Run本身，而是Solver读取Run参数的入口文件；专用副本的`INPUT`必须指向阶段二专用Run。

## 配置任务获授权后，AI允许修改的内容

使用者已明确要求配置，或取得“允许修改项目内MATLAB脚本与YAML、安装依赖、执行预检”的确认后，AI修改下表中的本机配置，并通过`capture_phase2_simfile`更新专用simfile和`runtime`中的路径、来源记录。项目根目录、模型、用例、数据和报告路径均由脚本自动定位，不得再写死目标机桌面路径。

| 文件 | 修改内容 |
|---|---|
| `01_一键启动脚本/run_single_python_case.m` | `pythonExe`、`trucksimSolverDir` |
| `01_一键启动脚本/run_batch_python.m` | `pythonExe` |
| `01_一键启动脚本/run_local_preflight.m` | `pythonExe`、`trucksimSolverDir` |
| `05_python_controller/config/vehicle_config.yaml` | `trucksim.run_name`（仅已确认时）、`trucksim.road_base_mu`（仅确认道路基准值后） |

AI不得修改：

- `run_case_python.m`中的项目根目录逻辑；默认用例已相对定位。仅当使用者指定其他TXT用例时才修改用例文件名。
- `.slx`文件中的模型结构或连线。实际运行脚本会将TruckSim S-Function的`SIMFILE`设置为`runtime/trucksim_phase2.path`所指向的TruckSim数据目录内专用入口。
- TruckSim程序目录、数据目录中的`simfile.sim`、`.par`文件。配置阶段只读取，不写入。

## 安装依赖与只读验证

AI在使用者已明确要求配置或已获确认后按如下步骤操作。

### 1. 安装或验证Python依赖

在`05_python_controller`目录中使用已确认的Python执行：

```powershell
& "<python.exe完整路径>" -c "import yaml,numpy,matplotlib,docx;print('python core deps ok')"
```

缺少时安装：

```powershell
& "<python.exe完整路径>" -m pip install -r "<阶段二项目根目录>\05_python_controller\requirements.txt"
```

若需要尝试TruckSim COM，再执行`& "<python.exe完整路径>" -m pip install pywin32`。即使已安装`pywin32`，TruckSim COM也可能因目标机未注册或权限限制而不可用；当前 YAML 默认直接按`trucksim_phase2.path`记录的专用simfile定位并修改关联`.par`文件。该路径支持 `road_grade` 百分数和 `straight_road` / `hill_20deg` 两种道路高程场景；换机后应先运行离线测试，再做低速真实联仿确认车辆响应。

### 2. 运行MATLAB只读预检

将MATLAB当前目录切换到：

```text
<阶段二项目根目录>\01_一键启动脚本
```

运行：

```matlab
run_local_preflight
```

预检检查Python解释器及核心依赖、solver、`Matlab84+`、项目内阶段二入口、固定 `PORTS_IMP 1,6` / `PORTS_EXP 1,27` 接口、入口 `INPUT` 所指向的参数文件、模型和TCP客户端文件；不启动仿真、不启动Python服务，也不修改TruckSim数据。端口检查是当前固定接口的静态基线核对，不代替后续真实联仿中的模型信号验证。

### 3. Python离线测试

确认没有真实仿真或`tcp_server.py`正在占用端口`50007`后，执行：

```powershell
cd "<阶段二项目根目录>\05_python_controller"
& "<python.exe完整路径>" tests\test_controller.py
& "<python.exe完整路径>" tests\test_server.py
& "<python.exe完整路径>" tests\test_report.py
```

三条命令均无报错并显示通过，即表示Python控制器、TCP服务和报告生成逻辑可用。报告测试只在临时目录生成合成文件，不会运行TruckSim，也不会修改历史联仿数据和报告。

## 真实仿真仅在使用者另行要求后执行

使用者明确要求运行前，AI必须说明：正式单工况或批量运行会根据TXT修改TruckSim工况；当前YAML默认优先修改`trucksim_phase2.path`记录的专用simfile关联的`Run_all.par`和其他`.par`文件，并创建备份，不依赖COM。`road_friction`只写`MY_FRICTION=目标值/road_base_mu`，不会修改道路文件的`MU_ROAD_CONSTANT`；坡度和道路高程场景只修改阶段二专用`Run_all.par`，不会修改共享的`Roads/*.par`。

使用者确认阶段二专用Run、`trucksim_phase2.sim`及关联数据已备份且允许写入后，AI才可：

1. 在MATLAB运行`run_case_python`做一个单工况（默认 40 km/h 阶跃；若使用者选择低速首测，先将 `caseFile` 改为现有的 `step_steer_python_20kmh.txt` 或 `sine_steer_python_15kmh.txt`）。
2. 检查日志中存在`CONFIG_READY`、`HANDSHAKE_OK`、`STOP_OK`、`SERVER_STOPPED`。
3. 检查同一运行目录的`*_trucksim_io.csv`和`*_python_signals.csv`，两者`sim_time_s`末值均应达到TXT的停止时间。
4. 检查CSV、PNG和Word报告均生成后，再运行`run_batch_python`。
5. 报告中的`execution_status=PASS`只表示运行和数据完整；在项目没有规定统一控制效果阈值时，`acceptance_status`应保持`NOT_EVALUATED`。

## AI完成配置后的交付内容

AI最终应向使用者汇报：

1. 已定位的Python版本和完整路径。
2. 已定位的TruckSim solver目录、`Matlab84+`目录、源`simfile.sim`及TruckSim数据目录中`simfile_phase2.sim`的完整路径。
3. `runtime/trucksim_phase2.path`是否已更新为目标机路径；YAML与MATLAB是否均通过该记录指向同一专用入口，以及该入口的`INPUT`是否属于阶段二Run。
4. 修改过的项目文件与变量清单。
5. 预检和Python离线测试的结果。
6. 是否尚未执行真实仿真，以及真实仿真会修改TruckSim`.par`数据的提醒。

若AI无法确认目标Run、实际`simfile.sim`或TruckSim数据写入许可，应停止在只读检查阶段并如实报告，不能凭旧电脑路径、文件名或历史报告推测。
