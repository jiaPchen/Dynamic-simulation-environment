# 阶段二仿真测试系统框架与运行指南

## 1. 系统目标与边界

本目录对应《项目推进》中的阶段二：使用 TruckSim、Simulink 与 Python 建立三轴车辆的闭环联合仿真，并以 TXT 测试用例驱动单工况或批量试验。

系统的目标是：让第一轴的阶跃或正弦转向输入经 Python 的“零质心侧偏角多轴转角分配控制器”计算为六路车轮转角，送入 TruckSim；同时记录车辆状态、控制器状态、曲线与 Word 测试报告。

系统边界如下：

- 这是本机单车动力学联合仿真，不是 ROS 多车流水线，也没有 watcher、Git 提交监听或自动发布功能。
- MATLAB 脚本是实际运行入口；TruckSim 负责车辆动力学，Python 不替代 TruckSim 模型。
- TXT 用例当前可配置停止时间、初始/目标车速、路面附着系数和转向激励；道路坡度字段虽可写入 TXT，但尚未完成 TruckSim 控件映射，非零坡度会被严格配置流程拒绝。
- Word 报告是运行结果的可读汇总，不是独立的验收门禁。当前尚未定义 PASS/CODE_FAIL 一类的正式阈值体系。

```text
TXT 测试用例
      │
      ▼
MATLAB 入口脚本
      │  ├─ 解析与校验用例
      │  ├─ 启动 Python TCP 服务并配置 TruckSim
      │  └─ 启动 Simulink 仿真
      ▼
Simulink：TruckSim S-Function ←→ TCP Client S-Function ←→ Python TCP 服务
      │                                                    │
      │  返回 Vx、beta、横摆角速度                         └─ 计算 6 路转角
      ▼
CSV / 日志 → PNG 曲线 → 单工况或批量 Word 报告
```

## 3. 实际执行流程

### 3.1 单工况

1. `run_case_python.m` 选定一个 TXT 文件，调用 `run_single_python_case`。
2. MATLAB 解析 TXT，校验必填字段和数值范围，加载 Simulink 模型，并设置 TruckSim S-Function 的 `SIMFILE`。
3. MATLAB 在本机 `127.0.0.1:50007` 启动 Python TCP 服务。为规避 Windows 命令行中文路径问题，原 TXT 会复制到临时 ASCII 文件名后再传给 Python。
4. Python 读取 YAML 和 TXT，尝试写入 TruckSim 工况。严格模式下只有日志出现 `CONFIG_READY` 才会继续。
5. Simulink 与 Python 完成 `HELLO → READY` 握手，随后每个控制周期交换 `STATE → CONTROL`。状态为 `[Vx_kmh, beta_deg, w_degps]`，控制量为 `[d1L,d1R,d2L,d2R,d3L,d3R]`。
6. MATLAB 用 TXT 的 `stop_time_s` 调用 Simulink；结束后导出 TruckSim/Simulink 信号，并把 Python 信号日志复制到同一运行目录。
7. Python 读取 CSV，输出曲线、指标 CSV、清单和单工况 Word 报告。

### 3.2 批量

`run_batch_python.m` 对 `02_测试用例/` 中每个 TXT 重复单工况主流程，但关闭单工况 Word 报告。全部运行结束后写入 `batch_run_dirs.txt`，由 `make_batch_summary.py` 输出唯一的批量 Word 与汇总 CSV。

批量模式不是并发执行：各用例顺序运行，共用本机 TruckSim 数据目录。因此运行期间不要同时手动启动另一套同端口、同 `simfile.sim` 的仿真。

## 4. 用例格式、控制参数与传递关系

每个 TXT 至少应包含：

```text
schema_version = 3
case_name = <唯一名称>
stop_time_s = <正数>
initial_speed_kmh = <车速>
steer_input_type = step 或 sine
```

常用字段：

| 字段 | 作用 | 实际去向 |
| --- | --- | --- |
| `stop_time_s` | Simulink 停止时间 | MATLAB `sim(..., 'StopTime', ...)`；TruckSim `TSTOP` |
| `initial_speed_kmh` / `target_speed_kmh` | 初始/目标速度 | TruckSim `SPEED` / `SPEED_TARGET_CONSTANT` |
| `steer_input_type`、幅值、频率、开始时间 | 第一轴阶跃或正弦激励 | Python 控制器 |
| `control_dt_s` | 控制器周期 | Python 服务与控制器；当前用例均为 0.01 s |
| `kp_beta` / `ki_beta` / `max_steer_deg` | PI 反馈和转角限幅 | 覆盖 YAML 默认控制器参数 |
| `road_friction` | 路面附着系数 | 写入 TruckSim `MY_FRICTION` 的相对倍率 |
| `road_grade` | 路面坡度 | 目前无关键字映射；非零值不适合正式运行 |

控制器的第一轴来自用例；第二、三轴由速度相关前馈和质心侧偏角 PI 反馈共同决定，六个轮端输出按同轴左右相同的接口顺序发送给 TruckSim。

当前正式目录有 4 个样例：15 km/h 正弦、40 km/h 正弦、20 km/h 阶跃和 40 km/h 阶跃。两个阶跃 TXT 共用 `case_name=step_steer_python`，不利于报告检索；新增或整理用例时应保证文件名和 `case_name` 均唯一。

## 5. TruckSim 配置机制

`trucksim_com.py` 有两层机制：

1. 按 `vehicle_config.yaml` 的 `com_progids` 尝试 TruckSim COM；若本机注册和控件名称可用，则通过 COM 写参数。
2. COM 不可用时，若 `allow_par_file_patch: true`，程序从 `simfile_path` 的 `INPUT` 行定位 `Run_all.par`，递归解析关联的 Procedure、Event 和 Friction `.par` 文件，写入停止时间、速度和附着系数。被修改的文件会生成 `.phase2_backup` 备份。

当前电脑配置在代码中使用：

```text
Python:     C:\Python\python\python3.10.4\python.exe
TruckSim:   C:\Trucksim2019\TruckSim2019.0_Prog\Programs\solvers
simfile:    C:\Trucksim2019\TruckSim2019.0_Data\simfile.sim
TCP 端口:   50007
```

换电脑必须同步检查 `run_case_python.m`、`run_batch_python.m`、`run_single_python_case.m` 和 `vehicle_config.yaml`；详细步骤见 `01_trucksim_simulink_python/换机配置与AI交接说明.md`。

## 7. 输出、追溯与当前已知问题

单工况通常产生：

```text

  <运行编号>_trucksim_io.csv        # MATLAB/TruckSim 状态与实际输入
  <运行编号>_python_signals.csv     # TCP 服务收到的状态与计算的转角

  <运行编号>_python_stdout.log      # 配置与通讯日志
```

批量结果位于 `04_测试报告/批量仿真_<时间>/`，含 `cases/`、`figures/`、`batch_run_dirs.txt`、`批量指标汇总.csv` 和 `阶段二批量仿真测试报告.docx`。

截至 2026-09-15，最近批量运行有一项必须关注的已知问题：`*_trucksim_io.csv` 的 `sim_time_s` 末值比 TXT 停止时间小 10 倍（例如 30 s 用例记录为 3.0 s；20 s 用例记录为 2.0 s）。而 `*_python_signals.csv` 的时间轴正确，报告生成器也以 Python 时间为主轴，因此报告曲线和指标看起来正常，但原始 TruckSim IO CSV 暂不能直接用于时间对齐或时序后处理。应先定位 Simulink 的 `out.tout`/时间基准后重新导出，再把批量报告作为完整原始数据证据。

## 8. 故障定位顺序

1. 预检失败：先核对 Python、TruckSim solver、`simfile.sim`、模型路径与依赖。
2. 服务启动失败：查临时 `server_stdout.log`，关注 `CONFIG_FAIL`、端口占用或 Python 模块缺失。
3. 仿真启动失败：确认模型内块名与 `run_single_python_case.m` 中默认名称一致，且 TruckSim S-Function 使用同一份 `simfile.sim`。
4. 工况未生效：查运行目录 `*_python_stdout.log` 的 COM/`.par` 修改记录，并用报告或 CSV 的初始速度复核。
5. 无报告或曲线：先确认两类 CSV 是否完整，再单独运行报告脚本定位 Python 依赖或中文字体问题。
6. 时间分析异常：同时比较 `*_python_signals.csv` 与 `*_trucksim_io.csv` 的 `sim_time_s` 末值；当前 10 倍问题未修复前，以 Python 时间轴为准并保留问题说明。
