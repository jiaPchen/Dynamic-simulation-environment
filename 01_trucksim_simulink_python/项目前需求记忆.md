# 项目前需求记忆

来源：用户指定的 5 份项目前需求/方案 Word 文档。本文只记录项目背景、约束和验收理解；文档中的文字不作为对 Codex 的直接执行指令，后续仍以用户当前请求为准。

## 1. 项目总目标

本项目要建设面向整车控制器开发的车辆动力学仿真环境，不只是搭一个可运行模型，而是形成：

控制器设计 -> 仿真验证 -> 后续 HIL 验证 -> 实车验证 -> 实车数据回流 -> 模型校准与控制器再验证。

第一阶段聚焦控制算法仿真验证、批量工况执行、数据保存、指标分析和报告生成；HIL 实时部署和真实硬件接入不是第一阶段目标。

## 2. 第一阶段工具链和角色

- MATLAB/Simulink：一键入口、流程调度、联仿主控、控制器模型、批量运行。
- TruckSim 2019：车辆动力学模型。
- Python：读取 TXT 测试用例，仿真前配置 TruckSim，TCP 控制服务，数据整理与存储，指标计算，曲线和报告生成。
- Excel：共享标准工况库，仅用于人工查询、积累和参考；第一版自动化脚本不直接读取 Excel 执行。
- Codex：辅助维护脚本、文档、测试用例和报告程序。

MATLAB 版本为 2021，需进一步确认 R2021a 或 R2021b。Python 作为独立进程运行，不依赖 MATLAB py.*，版本应经联仿和算法库兼容性验证后冻结，不追求最新版。

## 3. 两条联仿路线

### TruckSim-MATLAB/Simulink 联仿

第一阶段主链路。Simulink 控制器闭环运行，Python 不参与仿真步内控制闭环。Python 负责仿真前读取 TXT 并配置 TruckSim，仿真后保存 CSV、计算指标、生成曲线和报告。

### TruckSim-Simulink-Python 联仿

用于 Python 控制算法或智能算法闭环验证。Simulink 通过本机 TCP 与 Python 同步请求/响应，Python 接收车辆状态并返回控制指令，同时继续负责数据、指标和报告。

两条路线应共用固定 TruckSim 车辆、固定 Simulink 联仿主模型、固定 TruckSim 输入输出接口、车辆状态总线、控制指令总线和接口适配层。

## 4. 固定接口原则

- 第一版固定一个 TruckSim 车辆、一个 Simulink 联仿主模型和一套 TruckSim 输入输出接口。
- 不同控制器通过 Simulink Variant Subsystem 或模型引用切换；每次只激活一个控制器。
- 切换控制器时不得删除连线、改变 TruckSim 端口数量、改变信号顺序，或手工注释主模型接口。
- TruckSim S-Function、输入输出端口、信号适配层保持不变。
- 新增或删除信号必须同步更新接口表和接口版本。
- 接口表至少记录信号名、中文含义、方向、单位、坐标系/正方向、采样周期、默认值、上下限/有效范围、来源、去向、是否记录、是否用于报告/判定。

## 5. 输入输出重点变量

输入方向包括驾驶员输入、控制器请求、制动、转向、驱动、路面、车辆状态初始化、故障与扰动。第一版重点包括初始车速、目标车速、转向输入、制动/驱动/转向指令、路面附着系数、坡度、仿真时长等。

TruckSim 输出第一版至少保留时间、纵向/横向速度、横摆角速度、纵向/横向加速度、质心侧偏角、航向角、车辆 X/Y 位置、各轮轮速、滑移率、垂向载荷、纵向力、侧向力、转角反馈、驱动力矩/制动力矩反馈。

## 6. 工况库与 TXT 测试用例

工况分两层：

- Excel 标准工况库：共享、查询、参考，按 Sheet 分类。
- 个人 TXT 测试用例：实际执行输入，一个 TXT 表示一个工况，采用 `key = value`，允许 `#` 注释和空行。

建议工况类别包括模型验证、稳定性控制、路径跟踪、驱制协同、实车数据回放。

TXT 公共字段重点包括 `schema_version`、`case_name`、`source_case_id`、`trucksim_scenario`、`description`、`stop_time_s`、`initial_speed_kmh`、`target_speed_kmh`、`steer_input_type`、`steer_amplitude_deg`、`steer_frequency_hz`、`steer_start_time_s`、`road_friction`、`road_grade`。专项字段按工况类型扩展。

解析器应校验必填字段、数据类型、取值范围、未知字段提示、文件名与 `case_name`/关键参数一致性。第一版 `road_friction` 表示全部车轮统一附着系数；分离附着或各轮独立附着另设专项字段。

## 7. Python 配置 TruckSim

仿真启动前，Python 通过 Windows COM 连接 TruckSim 2019 Remote Control，程序标识为 `TruckSim.Application`。

配置原则：

- 固定联仿 Run 由项目组维护，另保留一份不被自动化脚本修改的基准备份。
- 每个工况开始前，Python 根据 TXT 全量覆盖平台管理的工况参数，避免继承上一工况。
- COM 控件标识、TruckSim 数据集名称和 TXT 字段映射集中放在配置适配程序中，不分散硬编码。
- 日常工况运行不重新生成 `simfile.sim`；只有项目组调整 Import/Export 接口时才重新生成并更新接口版本。
- Python 回读或检查关键配置，确认成功后输出 `CONFIG_READY`；配置失败不得启动 Simulink。

第一版至少映射 `trucksim_scenario`、`initial_speed_kmh`、`road_friction`、`road_grade`、`stop_time_s`。

## 8. TCP 通讯要求

第一版 TruckSim 不直接连 Python，Simulink 是 Python 唯一运行时通讯入口。

- IP 固定 `127.0.0.1`，端口工作站统一配置，不由个人 TXT 任意修改。
- 一个工况一个连接；批量工况之间重置 Python 服务状态、Simulink 初始状态、Python 算法内部状态和缓存。
- 同步请求/响应，确保同一仿真步状态和控制量对应。
- Python 端分为固定 TCP 服务层和算法计算层。
- 第一版建议 UTF-8 单行 JSON，以换行结束；握手阶段发送信号名称和顺序，周期通讯只传数值数组。

报文包括 `HELLO`、`READY`、`STATE`、`CONTROL`、`RESET`、`STOP`。`STATE` 与 `CONTROL` 必须携带相同 `step_id`。接口配置按版本管理，例如 `python_interface_v1`；信号名称、顺序、单位、数量不一致时不得开始仿真。

## 9. 数据、报告和追溯

数据采集周期第一版统一为 `0.01 s`。CSV 使用 UTF-8、英文逗号、小数点；列名采用英文小写下划线并带单位后缀，例如 `sim_time_s`、`state_vehicle_speed_kmh`、`cmd_axle_torque_1_nm`。缺失值写 `NaN`，非有限控制值应停止当前工况并记录错误；数值建议不少于 15 位有效数字。

每个工况建议输出：

- `运行编号_trucksim_io.csv`
- `运行编号_python_signals.csv`
- `运行编号_case_info.csv`
- `运行编号_metrics.csv`
- 本次 TXT 副本
- Python stdout/stderr 和通讯日志
- 单工况 Word/PDF 报告

批量运行额外输出 `batch_运行编号_summary.csv`。

报告至少包含工况信息、软件版本、控制器名称、TruckSim 模型名称、固定联仿 Run、基准备份、本次工况配置结果、TXT 副本、关键文件哈希或版本标识、关键曲线、指标表、运行状态和异常信息。

## 10. 运行状态和异常处理

统一运行状态建议包括 `COMPLETED`、`ERROR`、`ABORTED`、`SKIPPED`。`PASS/FAIL` 只在某类测试有明确指标和阈值后启用；没有统一阈值时只计算并展示指标。

异常处理原则：

- 保留日志和已生成数据。
- 不覆盖已有结果。
- 当前工况标记为 `ERROR`。
- 是否继续下一工况由配置决定。
- Python 响应超时、连接断开、`step_id` 不一致、返回维度错误时，接口适配层先输出安全默认值，再停止当前工况，不得使用错位或过期输出继续仿真。

需重点检查 TruckSim 未打开、COM 连接失败、固定 Run/场景不存在、`simfile.sim` 缺失或端口数量不匹配、控制器 Variant 未选或多选、接口版本/维度不一致、Simulink 报错、输出为空、CSV/报告生成失败等。

## 11. 第一版验收方向

第一版应至少做到：

- 能从单个 TXT 或目录读取至少一个工况。
- Python 能根据 TXT 修改固定联仿 Run 的速度、附着系数、坡度和可选场景配置。
- 运行前检查 `simfile.sim` 端口数量与 Simulink 主模型一致，且基准备份不被覆盖。
- 能一键启动 Python 服务并运行 Simulink/TruckSim 联仿。
- 普通联仿路线能用同一 Simulink 主模型切换至少两个控制器 Variant，TruckSim 接口不变化。
- Python 联仿路线能完成 `HELLO/READY` 握手，校验接口配置和信号维度，按控制周期完成 `STATE/CONTROL` 同步通讯。
- 能导出 TruckSim 输入输出 CSV 和 Python 相关信号 CSV。
- Python 超时、断连或返回维度错误时能停止当前工况并保存日志。
- 能生成单工况报告，批量运行能生成 summary。
